Ship Validation Flow

The pre-launch inspection

Right-click the helm and the inspection begins. Every gate below must pass in order — hull, helm, anchor, rudder, masts, sails, cannons, crew, weight, center of mass, buoyancy — before a hull earns the right to be called a ship.

Fig. 04 — Inspection gate chain
flowchart TD Start([Player Right-Clicks Helm Block]) --> Hull{Connected Hull?} Hull -- No --> Fail Hull -- Yes --> Helm{Helm Present?} Helm -- No --> Fail Helm -- Yes --> Anchor{Anchor Present?} Anchor -- No --> Fail Anchor -- Yes --> Rudder{Rudder Present?} Rudder -- No --> Fail Rudder -- Yes --> Masts{Masts Present?} Masts -- No --> Fail Masts -- Yes --> Sails{Sails Attached?} Sails -- No --> Fail Sails -- Yes --> Cannons{Cannons Valid?} Cannons -- No --> Fail Cannons -- Yes --> Crew{Crew Seats Valid?} Crew -- No --> Fail Crew -- Yes --> Weight{Weight Distribution OK?} Weight -- No --> Fail Weight -- Yes --> COM{Center of Mass OK?} COM -- No --> Fail COM -- Yes --> Buoy{Buoyancy Calculable?} Buoy -- No --> Fail Buoy -- Yes --> Class[Class Detection] Class --> Ready([Launch Ready]) Fail[Display Error Report] --> End([Return to Build Mode])

Damage Flow

Impact → module → flooding → broken

Every hit resolves to a specific module — hull, mast, rudder, anchor, cannons, or sails. Hull breaches start flooding; either path can push a module past its damage threshold into a broken state.

Fig. 09 — Damage resolution
flowchart TD Hit[Projectile Hit] --> Calc[Impact Calculation] Calc --> Module{Determine Module} Module --> Hull Module --> Mast Module --> Rudder Module --> Anchor Module --> Cannons Module --> Sails Hull --> Apply[Apply Damage] Mast --> Apply Rudder --> Apply Anchor --> Apply Cannons --> Apply Sails --> Apply Apply --> Flood{Hull Breach?} Flood -- Yes --> Flooding Flood -- No --> Broken{Threshold Exceeded?} Flooding --> Broken Broken -- Yes --> BrokenState[Broken State] Broken -- No --> Apply BrokenState --> Sinking{Flooding Critical?} Sinking -- Yes --> SinkingState[Sinking State]

17 — DESIGN PHILOSOPHY
“Build your own medieval warship and command it.”

Every system above serves one goal: preserve the vanilla+ feel — no floating menus dictating ship shape, no forced templates. The scanner reads whatever the player builds, validates it against physical logic, and only then promotes it to a living entity. Damage and sinking stay readable through block-level cues, not abstract health bars alone, so combat still feels like Minecraft.
